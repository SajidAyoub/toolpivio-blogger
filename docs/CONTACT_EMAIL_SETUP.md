# Activate contact email delivery

The contact integration is implemented, but the public endpoint in `src/contact/config.json` is deliberately empty. There is no Formspree account or verified recipient configured for this release. The published page therefore offers a local message draft and Copy draft/Clear controls; it cannot send messages. Drafts are held only in the current page, with no browser storage or background transmission. Copying uses the device clipboard. No Gmail password, OAuth token or private API key belongs in this repository.

1. Create a Formspree account and a form in its dashboard. Select the Gmail address you actually want to receive ToolPivio messages, complete Formspree’s recipient verification, and activate the form. Do not publish the recipient address in the site configuration.
2. Copy the **public form endpoint** from the form’s Integration panel. It has the shape `https://formspree.io/f/FORM_ID`. Only the real public endpoint is needed. Do not use an email-address URL, dashboard URL, token, API key, query string or fragment.
3. In the form’s Workflow validation settings where available, configure `name` as required text, 2–100 characters; `email` as required email, up to 254; `reason` as required text, up to 80; `message` as required text, 20–4,000; `tool_url` as optional URL, up to 500; and `consent` as required text. Field names must match these names exactly. Configure matching server validation if the selected project/plan supports it. Client validation is already implemented but can be bypassed; a public endpoint alone does not prove server rules are active. Provider validation remains an account-side setup step.
4. Enable the spam protection offered by your plan and review domain restrictions if available. The form includes Formspree’s documented `_gotcha` honeypot. The hosted form origin is `https://sajidayoub.github.io`, including when embedded in Blogger; test restrictions against that real origin. If you enable a CAPTCHA that requires provider-page confirmation, test the native HTML submission with JavaScript disabled as well as normal AJAX submission. Do not bypass required spam checks. This build does not load a CAPTCHA script or assume that a public site key exists.
5. Put the complete real endpoint into the sole setting in `src/contact/config.json`: `{ "endpoint": "your real public endpoint" }`. Replace the value, not the key. The build rejects endpoints outside exact HTTPS `formspree.io/f/<alphanumeric-id>` URLs and refuses credentials, query strings, fragments and extra configuration fields. This public form ID is not an authentication secret. Keep all account credentials private.
6. Run `npm run build` and `npm test`, plus `node tests/contact-browser.cjs` for intercepted-request checks. Review and merge the configuration/build change through a PR. Wait for GitHub Pages, then verify `https://sajidayoub.github.io/toolpivio-blogger/contact.html` and the existing Blogger Contact page. The iframe uses local CSS/JS assets and a secure resize handshake; the separately approved V4 theme handles its height. No OAuth change or new Blogger page registration is needed.
7. From the deployed page, submit one clearly identified real test message, using an email address you control and the privacy consent. Confirm that Formspree records the submission and that the intended Gmail inbox or spam folder actually receives it. Reply to verify the visitor’s `email` is used as Reply-To. A successful browser response means **provider acceptance**, not proof of inbox delivery or a reply. Do not mark email delivery verified until this receipt check succeeds. No real message was sent by the automated tests.
8. Check the Formspree dashboard’s current free-plan submission allowance, retention, anti-spam features and over-limit behavior before launch and periodically afterward. Free quotas and features can change; this implementation does not promise unlimited submissions. If the provider rejects, throttles or cannot confirm a request, the draft remains available and the client never retries a POST automatically. Keep a copy before deliberately resending an uncertain request, because it may already have been accepted.

The configured form transfers name, email, reason, message, optional URL and consent to Formspree and the owner’s configured inbox. Formspree may process connection information and store submissions according to its policy/account settings. Calculator values and image/PDF files continue to be processed locally and are not attached to contact requests. Review the updated Privacy/About/Terms wording before activating the endpoint.

The native HTML form has a standard provider POST action and required fields, so it can submit without JavaScript and opens the provider’s confirmation in a separate tab. With no endpoint configured there is no submit-capable form at all, including without JavaScript. Automated browser tests build a temporary configured fixture and intercept every provider request; no test mode or fake-success handler ships in production.
